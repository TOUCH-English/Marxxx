# 开发与审核流程（2026-10-23 起）

用户的最终目的：投资新手，长期把一部分资金交给系统，在设定的资金和风险边界内自动找机会、自动买卖，希望长期赚钱。
这里的「专业角色」是按专业分工、各自独立审核的 AI 审核员，不是持牌的真人专业人士；不构成投资建议，也不保证收益。

## 角色与职责

| 角色 | 负责什么 | 什么时候 |
| --- | --- | --- |
| 产品负责人 / 总协调（助手本人） | 把用户目标变成需求、排优先级、整合各方意见、向用户用中文解释 | 全程 |
| 风控经理 | 找出亏损可能超过设定上限的情况、保护失效的情况、意外下单；给出上真钱前的 go/no-go 清单 | 每次重大改动后、上真钱前 |
| 量化研究员 / 交易员 | 评估选股和买卖逻辑是否合理、费用是否吃掉利润；设计评估方法和及格标准 | 每次策略改动后、每个阶段结束 |
| 软件质量 / 代码审核 | 独立查新代码的错误，用测试验证 | 每次发布前 |
| 历史回测员 | 用过去的数据模拟系统表现，并和「买大盘指数持有」比较 | 新策略上线前 |
| 模拟操盘复盘员 | 每周复盘纸上交易的真实决策：买了什么、为什么、赚亏、AI 花费 | 每周 |
| 新手体验审核 | 检查页面和报告新手能不能看懂 | 有页面改动时 |
| 用户（最终决定人） | 批准资金、风险上限、是否进入下一阶段、是否用真钱 | 关键节点 |

规则：每位审核员只拿到代码和背景，不拿到其他人的结论，以免被带偏。
所有发现都要经助手核实后才修复；修复后要补自动化测试，再在 Mac 上只读验证，最后才交给用户。

## 历史数据检验（用户要求：不用等真实数据）

能做，但要先说清楚三个限制：
1. **AI 的「未来泄漏」**：Claude 训练时可能已经知道过去某段时间各股票的走势。用模型训练资料截止日期以前的历史去测 AI，成绩会虚高，不可信。
   因此 AI 只用「模型训练资料截止之后」的那段历史来测。当前模型 claude-opus-5-5 的可靠知识截止于 2026 年 6 月，
   所以只有 2026-07-01 之后的数据可用（换模型时要重新确认）。
2. **幸存者偏差**：moomoo 条件选股只能给出「今天」的市值和成交额。用今天的名单回测过去，会挑到后来涨起来的公司，同样让结果偏乐观。
   因此回测改用固定的大型股名单，并在报告中写明这一偏差。
3. **历史 K 线额度**：每 30 天最多 300 只不同证券（目前已用很少）。回测名单要控制在约 60 只以内，给日常运行留余量。

分三层做：

| 层次 | 内容 | 花费 | 能回答什么 |
| --- | --- | --- | --- |
| A. 规则回测（不用 AI） | 2–3 年日线：同样的选股排序、风控、止损和费用；对比 SPY 买入持有 | 免费 | 规则骨架扣费后有没有优势 |
| B. AI 历史模拟 | 只用模型训练资料截止之后的几个月，每个交易日让 Claude 决策一次 | 估计 5–15 美元，另行批准；目前暂缓（无泄漏样本太短，见审核文档「第 3 批进展」） | AI 加上去是变好还是变差 |
| C. 纸上交易（正在进行） | 真实行情、真实 Claude，往前跑 | 每月不超过 30 美元 | 真实环境下的表现与稳定性 |

及格标准由量化研究员给出建议后，交用户确认。原则：
- 扣除费用后不比 SPY 差；
- 最大回撤在设定范围内；
- 交易次数足够多才下结论；
- 历史回测再好，也要通过 C 才考虑真钱。

### A 层怎么运行（在 Mac 上，只读）
```
python scripts/history_backtest.py check   # OpenD、K 线额度、财报日历/行业权限、SPY 日 K
python scripts/history_backtest.py fetch   # 约 3 年日 K，默认至少保留 150 只额度给自动交易
python scripts/history_backtest.py run     # 用本机官方费用表、已确认风控版本、当前授权的资金与停止线
```
报告保存在 `data/history/reports/`（`.md` 给人看，`.json` 留档）。
